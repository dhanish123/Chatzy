CHATZY - PRODUCTION DEPLOYMENT CHECKLIST

PRE-DEPLOYMENT:
✓ All tests passing
✓ Code reviewed
✓ Security audit completed
✓ Performance optimized
✓ Error handling robust
✓ Logging configured
✓ Environment variables documented

STEP 1: DATABASE DEPLOYMENT
1. Create MongoDB Atlas account (https://www.mongodb.com/cloud/atlas)
2. Create database cluster
3. Configure network access (whitelist IPs)
4. Create database user with strong password
5. Get connection string
6. Test connection locally
7. Create database indexes (if needed)
8. Configure automatic backups

MongoDB Connection String Format:
mongodb+srv://username:password@cluster-name.mongodb.net/database-name

STEP 2: BACKEND DEPLOYMENT

Option A: Railway (Recommended for beginners)
1. Create Railway account (https://railway.app)
2. Connect GitHub repository
3. Create new project
4. Set environment variables:
   - MONGODB_URI
   - JWT_SECRET
   - NODE_ENV=production
   - FRONTEND_URL
   - API_URL
   - SOCKET_URL
5. Deploy automatically
6. Get backend URL
7. Set custom domain (optional)

Option B: Render
1. Create Render account (https://render.com)
2. Create new Web Service
3. Connect GitHub
4. Set build command: npm install
5. Set start command: npm start
6. Add environment variables
7. Deploy

Option C: Fly.io
1. Create Fly.io account (https://fly.io)
2. Install flyctl CLI
3. Run: flyctl launch
4. Configure fly.toml
5. Set environment variables
6. Run: flyctl deploy

Backend URL Examples:
- Railway: chatzy-api-xxxxx.railway.app
- Render: chatzy-api.onrender.com
- Fly.io: chatzy-api.fly.dev
- Custom: api.yourdomain.com

STEP 3: WEB FRONTEND DEPLOYMENT

Option A: Vercel (Recommended)
1. Create Vercel account (https://vercel.com)
2. Import project from GitHub
3. Select framework: Vite
4. Set build command: npm run build
5. Set environment variables:
   - VITE_API_URL=https://your-backend-url/api
   - VITE_SOCKET_URL=https://your-backend-url
6. Deploy
7. Configure custom domain

Option B: Netlify
1. Create Netlify account (https://netlify.com)
2. Connect GitHub
3. Build settings:
   - Command: npm run build
   - Directory: dist
4. Set environment variables
5. Deploy
6. Configure custom domain

Option C: Cloudflare Pages
1. Create Cloudflare account
2. Connect GitHub
3. Set build command: npm run build
4. Set output directory: dist
5. Add environment variables
6. Deploy

Web URL Examples:
- Vercel: chatzy.vercel.app or yourdomain.com
- Netlify: chatzy.netlify.app or yourdomain.com
- Cloudflare: yourdomain.com

STEP 4: MOBILE APP DEPLOYMENT

Option A: Expo Application Services (EAS)
1. Create Expo account (https://expo.dev)
2. Install EAS CLI: npm install -g eas-cli
3. Create eas.json in mobile directory
4. Configure environment variables
5. Build for Android: eas build --platform android
6. Build for iOS: eas build --platform ios
7. Create stores (Google Play, Apple App Store)
8. Upload builds
9. Configure push notifications

Option B: Manual Build
1. Android:
   - Generate release keystore
   - Build APK/AAB
   - Sign with keystore
   - Upload to Google Play

2. iOS:
   - Create Apple Developer account
   - Create certificates and profiles
   - Build IPA
   - Upload to TestFlight/App Store

STEP 5: DOMAIN SETUP

1. Purchase domain (Namecheap, GoDaddy, etc.)
2. Configure DNS:
   - yourdomain.com → Web frontend
   - api.yourdomain.com → Backend API
   - socket.yourdomain.com (optional, same as api)

3. Point nameservers to hosting provider
4. SSL certificates (auto-renew):
   - Vercel: Free SSL
   - Netlify: Free SSL
   - Railway: Free SSL
   - Custom: Let's Encrypt

STEP 6: ENVIRONMENT VARIABLES

Backend (.env on hosting platform):
MONGODB_URI=mongodb+srv://user:pass@cluster.mongodb.net/chatzy
JWT_SECRET=generate-32-char-random-string
PORT=5000
NODE_ENV=production
FRONTEND_URL=https://yourdomain.com
MOBILE_URL=exp://yourdomain.com
API_URL=https://api.yourdomain.com
SOCKET_URL=https://api.yourdomain.com

Web (.env on hosting platform):
VITE_API_URL=https://api.yourdomain.com/api
VITE_SOCKET_URL=https://api.yourdomain.com

Mobile (.env on hosting platform):
EXPO_PUBLIC_API_URL=https://api.yourdomain.com/api
EXPO_PUBLIC_SOCKET_URL=https://api.yourdomain.com

STEP 7: SSL/HTTPS

1. Verify certificates valid
2. Test HTTPS in browser
3. Configure HSTS headers (recommended)
4. Test Socket.IO over WSS (secure WebSocket)
5. No HTTP traffic (redirect to HTTPS)

STEP 8: MONITORING & LOGGING

1. Set up error tracking (Sentry):
   - Create account
   - Install SDK in backend
   - Configure environment
   - Test error reporting

2. Set up performance monitoring:
   - Use hosting provider's built-in tools
   - Monitor response times
   - Check error rates
   - Review resource usage

3. Set up logs:
   - Backend logs to stdout
   - Hosting platform collects logs
   - Review logs daily
   - Set up alerts

STEP 9: BACKUP & RECOVERY

1. Database backups:
   - MongoDB Atlas handles automatically
   - Enable point-in-time recovery
   - Test restore procedure

2. Application backups:
   - GitHub is version control
   - Tagged releases for deployments
   - Document current state

3. Recovery plan:
   - Document recovery procedure
   - Test restore process
   - Estimate RTO/RPO

STEP 10: SECURITY HARDENING

1. CORS:
   - Whitelist specific origins only
   - Not "*" in production
   - Verify headers correct

2. Rate limiting:
   - Configure on backend
   - Protect auth endpoints
   - Test limits

3. Input validation:
   - All endpoints validate input
   - File upload restrictions
   - SQL injection protection (N/A - MongoDB but still validate)

4. Secrets management:
   - No secrets in code
   - Use environment variables
   - Rotate JWT_SECRET periodically
   - Secure database credentials

5. HTTPS/TLS:
   - Enforce SSL/TLS
   - Modern protocol versions
   - Strong cipher suites

STEP 11: CDN & CACHING

1. Configure CDN (optional):
   - Cloudflare free tier
   - Cache static assets
   - Improve performance globally

2. Browser caching:
   - Set cache headers on static files
   - No-cache on API responses

STEP 12: LOAD TESTING

1. Test with expected users:
   - 100 concurrent users
   - Rapid message sending
   - Multiple file uploads

2. Monitor during test:
   - CPU usage
   - Memory usage
   - Database connections
   - Response times

3. Scale if needed:
   - More servers
   - Database optimization
   - CDN configuration

STEP 13: NOTIFY STAKEHOLDERS

1. Announce deployment
2. Share application URLs
3. Provide documentation
4. Gather initial feedback
5. Monitor for issues

STEP 14: POST-DEPLOYMENT

1. Monitor for 24 hours:
   - Check error logs
   - Verify features work
   - Check performance
   - Monitor resource usage

2. Set up alerts:
   - High error rates
   - Slow response times
   - Database issues
   - Server down

3. Document runbook:
   - How to deploy updates
   - How to rollback
   - Emergency contacts
   - Common issues

ROLLBACK PLAN:
If deployment fails:
1. Revert to previous version
2. Restore from backup if needed
3. Notify users
4. Investigate root cause
5. Fix and test thoroughly
6. Re-deploy

UPDATE PROCEDURE:
1. Test locally
2. Test on staging (if available)
3. Backup database
4. Deploy backend first
5. Verify backend working
6. Deploy frontend
7. Monitor for errors
8. Keep previous version accessible for rollback

MAINTENANCE:
- Weekly: Check logs and alerts
- Monthly: Review analytics and performance
- Quarterly: Security audit
- Yearly: Full disaster recovery test
